## 4. Доработка индивидуального проекта
- **Проектирование структуры реляционной базы данных (`data/workload.sqlite`):**
  1. Таблица `teachers` (преподаватели): `id` (INTEGER PRIMARY KEY), `name` (TEXT), `position` (TEXT), `department` (TEXT), `rate` (REAL);
  2. Таблица `disciplines` (дисциплины): `id` (INTEGER PRIMARY KEY), `name` (TEXT), `department` (TEXT), `semester` (INTEGER);
  3. Таблица `workloads` (поручения): `id` (INTEGER PRIMARY KEY), `teacher_id` (INTEGER, FK -> teachers), `discipline_id` (INTEGER, FK -> disciplines), `lectures` (REAL), `practices` (REAL), `labs` (REAL), `exams` (REAL), `total_hours` (REAL), `is_cancelled` (INTEGER).
- **Схема создания таблиц (`sql/schema.sql`):** Реализованы команды `CREATE TABLE IF NOT EXISTS` с обязательными ограничениями `PRIMARY KEY`, `NOT NULL`, `DEFAULT` и внешними ключами `FOREIGN KEY ... REFERENCES ... ON DELETE CASCADE`. Включена директива `PRAGMA foreign_keys = ON;`.
- **Подключение к базе данных (`db/database.py`):** Функция `get_connection()` настраивает подключение к SQLite, устанавливает `conn.row_factory = sqlite3.Row` для именованного доступа к полям кортежей и включает контроль ссылочной целостности `PRAGMA foreign_keys = ON`.
- **Импорт данных из JSON (`db/import_json.py`):** Реализован скрипт пакетного переноса данных с использованием `executemany()` и транзакционной защитой (`commit` / `rollback`), соблюдающий строгую очередность импорта (сначала независимые таблицы `teachers` и `disciplines`, затем зависимая таблица связей `workloads`).
- **Разработка и верификация SQL-запросов (`sql/queries.sql`):** Подготовлен набор из 12 прикладных запросов предметной области:
  - Выборка и сортировка (SELECT, ORDER BY);
  - Фильтрация записей (WHERE) по объему часов и ставкам;
  - Соединение таблиц (JOIN) для получения сводных карточек с именами преподавателей и дисциплин;
  - Подзапрос с оператором `NOT IN` для поиска нераспределенных (свободных) дисциплин;
  - Агрегатные вычисления (`COUNT`, `SUM`, `AVG`);
  - Группировка (`GROUP BY`) и фильтрация групп (`HAVING`) для анализа нагрузки преподавателей и распределения часов по семестрам.
- **Интеграция с Django:**
  - В приложении `disciplines` создано представление `available_disciplines` (`/disciplines/available/`), выполняющее параметризованный запрос с подзапросом `NOT IN` и отображающее результат через шаблон `available.html`;
  - В приложении `workloads` создано представление `statistics` (`/workloads/statistics/`), агрегирующее показатели кафедры через SQL и визуализирующее их в шаблоне `statistics.html`;
  - Обеспечена автоматическая синхронизация операций веб-интерфейса (добавление преподавателей, дисциплин, переключение активности поручений) с базой данных SQLite.
- **Организация навигации:** В единый навигационный шаблон `templates/includes/navigation.html` добавлены ссылки на «Свободные дисциплины» (`{% url 'disciplines:available' %}`) и «Статистика» (`{% url 'workloads:statistics' %}`).
- **Сохранение совместимости:** Доменные ООП-модели, консольное приложение `main.py` и JSON-хранилище полностью работоспособны.
